# Faed Dashboard UX

## Goal

Make Merchant and Admin interfaces:
- efficient;
- clean;
- data-first;
- understandable;
- not visually cluttered;
- not generic template dashboards.

## Distinguish contexts

Merchant/Admin interfaces must feel related to the public site but not identical.

Public UI:
- more visual;
- product discovery driven.

Dashboard/Admin UI:
- denser;
- more operational;
- table/list/form driven.

## Layout principles

- use clear page titles and page purpose;
- show important actions near the page title;
- keep navigation predictable;
- use summary stats only when useful;
- preserve strong table readability.

## Merchant dashboard priorities

Important surfaces:
- listings;
- stock;
- orders;
- B2B offers/deals;
- analytics;
- store settings.

The merchant should quickly answer:
- what needs my attention now?
- which listings need action?
- do I have orders/offers waiting?
- which stock is stale or low?
- how is recovery performing?

## Admin dashboard priorities

Important surfaces:
- merchant verification queue;
- listing moderation queue;
- disputes;
- catalog management;
- transaction monitoring;
- audit log.

The admin should quickly answer:
- what needs review?
- what is blocked?
- what is risky?
- what requires a decision now?

## Forms

Long forms must be chunked logically.
Prefer step-by-step or clearly sectioned layouts for:
- merchant onboarding;
- listing creation/editing.

Form rules:
- clear labels;
- concise helper text;
- inline field validation;
- avoid giant unstructured forms.

## Tables

Tables are useful but must remain responsive.
Rules:
- prioritize critical columns;
- avoid too many low-value columns;
- provide status/action clarity;
- support smaller screens thoughtfully.

## Analytics

Analytics should be decision-oriented, not decoration-oriented.

Show:
- recovered value;
- sell-through;
- channel split;
- stale inventory;
- order/deal volume.

Do not add charts only to “look professional”.
Use charts when they clarify a pattern better than numbers.

## Status and attention model

Differentiate:
- informational;
- needs action;
- risk/problem;
- completed.

Use consistent status styling across merchant/admin areas.
