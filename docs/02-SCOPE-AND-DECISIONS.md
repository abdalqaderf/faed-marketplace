## Listing moderation policy

For the validation-stage MVP:

- Merchant must be verified before creating/submitting listings.
- A new listing requires admin moderation before becoming public.
- Material changes to a live listing must return it to moderation.

Material changes include at minimum:
- product identity;
- category;
- condition;
- discount reason;
- defect disclosure;
- price/reference price;
- variant structure.

Simple stock quantity adjustments do not require re-review unless suspicious.

Implementation must keep moderation policy configurable so the platform can later move trusted merchants to post-moderation without schema redesign.

## Branding

Use `Faed` as the repository/application working name.

Do not scatter the brand name through business logic. UI branding should be centralized/configurable.

---

## English UI decision

All system-owned user-facing text is English:
- navigation;
- forms;
- validation;
- statuses;
- transactional email templates;
- admin interface;
- error pages;
- routes/slugs generated by the app.

Merchant-entered product text is Unicode-safe and is not technically restricted to ASCII.

---

## JOD rules

- Store money as `decimal(18,3)`.
- Use ISO currency code `JOD` in domain/data.
- UI may render `JOD 12.500`.
- Never calculate with `double`/`float`.

---

## Out-of-scope means not scaffolded

Do not create empty:
- payment modules;
- shipping-provider integrations;
- auction modules;
- warehouse modules;
- subscriptions;
- native API/mobile infrastructure;

just because they may exist later.

Future compatibility should come from clean domain boundaries, not unused code.
