# 22 — Visual Studio Baseline

## Purpose

The developer creates the first ASP.NET Core MVC project manually in Visual Studio before any coding agent modifies the repository.

This is intentional.

The goal is to:
- see exactly what Visual Studio generates;
- start from the official MVC + Identity template;
- establish a clean Git checkpoint before agent changes;
- let TASK-001 validate and adopt the generated baseline rather than replacing it.

---

```text
Faed/
├── AGENTS.md
├── CLAUDE.md

```

---

## Visual Studio project creation

Create:

```text
ASP.NET Core Web App (Model-View-Controller)
```

Use:

```text
Project name: Faed.Web
Framework: .NET 10
Authentication type: Individual Accounts
Configure for HTTPS: Enabled
```

Do not enable unless later required:
- Docker;
- container orchestration;
- unnecessary cloud integrations.

Target location:

```text
Faed/src/Faed.Web/
```

The solution should live at the repository root when practical:

```text
Faed/Faed.sln
```

or the current Visual Studio solution format equivalent.

Avoid accidental nesting such as:

```text
Faed/Faed/Faed.Web/
```

---

## What should exist after Visual Studio generation

Exact files may vary by Visual Studio/template version, but expect the functional equivalents of:

```text
src/Faed.Web/
├── Controllers/
├── Data/                         # initially, if template places Identity DbContext here
├── Models/                       # template-dependent
├── Properties/
│   └── launchSettings.json
├── Views/
├── wwwroot/
├── appsettings.json
├── appsettings.Development.json  # template-dependent
├── Program.cs
└── Faed.Web.csproj
```

Identity pages may come from the ASP.NET Core Identity Razor Class Library.

Do not scaffold every Identity page merely because the physical `.cshtml` files are not visible.

---

## Before letting an agent touch the code

The developer should:

1. restore/build the solution;
2. run the application;
3. confirm Home loads;
4. confirm Register/Login links/routes exist;
5. inspect the generated EF/Identity provider;
6. inspect `git status`;
7. commit this untouched or minimally verified baseline.

Suggested commit:

```text
chore: create MVC Identity baseline
```

This commit is the recovery checkpoint for the official Visual Studio-generated project.

---

## Database-provider note

Visual Studio/template behavior can differ.

If the generated Identity baseline uses SQLite while the Faed architecture requires SQL Server:

- do not panic;
- do not manually rewrite everything before TASK-001;
- let TASK-001 audit it;
- then migrate deliberately to SQL Server while preserving authentication behavior.

The final architecture remains SQL Server.

---

## Files generated by Visual Studio that normally belong in Git

Commit source/project artifacts such as:

- solution file;
- `.csproj`;
- `Program.cs`;
- controllers;
- Razor views;
- `wwwroot` template assets;
- `Properties/launchSettings.json` when it contains no secrets;
- EF migrations;
- source configuration files without secrets.

Do not commit generated build/user/local artifacts such as:

- `.vs/`;
- `bin/`;
- `obj/`;
- user secrets;
- local DB files;
- logs;
- test results.
